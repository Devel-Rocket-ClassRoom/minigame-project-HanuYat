## 게임 소개

- 복도를 걷다가 **이상현상이 있으면 되돌아가고, 없으면 전진**합니다. 판단이 맞으면 카운터가 1 오르고, 틀리면 0으로 돌아갑니다
- 카운터가 8에 도달하면 출구가 열립니다. 이상현상은 복도에 들어설 때마다 정해진 확률로 등장하며, 직전에 나온 항목은 연속으로 나오지 않습니다

## 구현

### 1. 복도 하나로 만든 무한 루프

- **기획 의도** — 복도를 매 루프마다 계속 새로 만들면 게임 메모리도 감당이 안 될 뿐더러, 짧은 제작 기간 안에 게임을 완성시키기 힘듭니다
- **구조** — 하나의 복도만 두고, 양 끝 문을 `E`로 열면 페이드 아웃 중간 시점에 플레이어를 시작 지점으로 옮기고 복도 상태를 초기화합니다. 화면이 다시 밝아지면 다음 루프로 이동합니다
- **한 지점에 모은 이유** — 위치 초기화 · 상호작용 오브젝트 리셋 · 이상현상 재추첨이 **페이드 아웃 도중에 함께** 일어나야 합니다. 셋 중 하나라도 밝아진 뒤에 실행되면 플레이어가 그 변화를 목격합니다

### 2. 이상현상을 계약으로 고정 — 17종

- 추상 클래스인 `AnomalyEffectBase`가 `Activate()` / `Deactivate()`만 계약으로 두고, 각 이상현상은 그 안에서 자기 방식대로 동작합니다. 이상현상 매니저는 구현을 모른 채 목록에서 하나를 고르기만 합니다
- 오브젝트 추가 · 제거, 색 변경, 조명 변화, 위치 · 회전, 스케일, 머티리얼 교체, 소리 이상, 화면 왜곡, 침수, 추격 등 총 **17종**으로 확장했고, 이상현상을 추가하고 싶을 때는 클래스 하나를 만들어 후보 목록에 넣으면 끝납니다

| :---: | :---: |
| ![새 떼](docs/gifs/anomaly-birds.gif) | ![화면 노이즈](docs/gifs/anomaly-noise.gif) |

- **직전 항목 연속 방지** — 처음에는 "직전 것과 같으면 다시 뽑기" 방식이었는데, 후보가 2개인 구간에서 25% 확률로 같은 게 연속으로 나왔습니다. 후보 풀에서 최근 사용분을 **미리 걸러내는** 방식으로 바꿔 구조적으로 차단했습니다

### 3. Firebase 리더보드

- 익명 로그인으로 계정을 만들고, **최단 클리어 시간**을 실시간 DB에 기록합니다
- 순위표는 상위 100명만 받아 오기 때문에, 순위 밖에 있는 사람은 자기 기록과 등수를 따로 조회합니다
- **닉네임 중복** — 두 사람이 같은 순간에 같은 닉네임을 넣으면 둘 다 성공해 버릴 수 있습니다.
  그래서 `nicknames/{닉네임}`에 사용자 ID를 먼저 적고, 이미 다른 ID가 있으면 그 자리에서 막습니다. 비어 있는지 보는 것과 적는 것이 한 번에 일어나기 때문에 중복이 될 일이 없습니다
- **도중에 실패한 경우** — 닉네임은 적혔는데 프로필 저장이 실패할 수 있습니다. 그대로 두면 곧 사라질 익명 계정이 그 이름을 계속 붙잡습니다. 실패하면 방금 적은 것을 지웁니다
- **서버 규칙으로 한 번 더 검증** — 기록은 본인 칸에만 쓸 수 있고, 닉네임이 프로필과 일치해야 합니다. 시간은 정해진 범위 안에서 **이전 기록보다 빠를 때만** 덮어써지고, 정의하지 않은 항목은 아예 저장되지 않습니다. 조작한 기록을 보내도 서버가 걸러냅니다

### 4. 에디터 툴

- `NavMeshBakeHelper` — 교실 NavMesh 베이크를 메뉴 한 번으로
- `GrassScatter` — 외부 지형에 잔디를 규칙대로 배치. 밀도와 스케일 범위를 지정하고 건물 자리는 제외합니다
